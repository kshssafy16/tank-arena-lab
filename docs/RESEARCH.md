## 정적 확인 방법과 결과

Managed 메타데이터/선택된 행동 메서드의 IL을 읽고, 실제 Stage 로더의 리소스 경로를 따라 TextAsset을 확인했다. `level0`~`level4`가 Stage 번호와 같다는 가정을 사용하지 않았다. 보호조치 우회·원본 패치·서비스 호출은 하지 않았다. 맵, IL, 도구, 체크섬은 `.private_reference/` 안에만 있다.

정적 분석으로 별점 계산 분기, 반복 시도 처리, 60초 상수, 일반/메가 피해와 독립 탄약, 암호 간격 17, 보급 증가량 1 및 상한 10, 종료 신호를 확인했다. Stage 6에는 매 턴 지형 변화와 NPC 이동이 있다. 모래·실패 행동의 일부 피해 함수는 팀전 모드에만 조건부로 적용되므로 매뉴얼을 그대로 모든 모드에 일반화하지 않았다. 구체적 비공개 점수표/맵은 개인 프로필에만 둔다.

분석에 사용한 도구는 개발 전용이며 제품 의존성이 아니다. [dnfile의 MIT 라이선스](https://github.com/malwarefrank/dnfile), [dncil의 Apache 2.0 소스](https://github.com/mandiant/dncil), [UnityPy의 MIT 라이선스](https://github.com/K0lb3/UnityPy)를 확인했다. 설치된 분석 패키지는 모두 ignored 디렉터리 내부에 한정했다. .NET SDK는 없어 해당 도구 경로를 사용하지 않았다. 도구 라이선스가 원본 자료의 재배포 권리를 부여하지는 않는다.

## 관찰 기록과 재현의 구분

사용자가 전해 준 참조 기록은 Stage 1의 7개 이동/발사 명령으로 7턴·3별 성공, 결과 후 연결 reset이다. 개발 중 원본 실행 화면에서 새로 관찰한 사실로 취급하지 않는다.

이번에 확보한 비공개 지도와 정적으로 확인한 초기 조건을 같은 엔진에 적용해 **전달받은 7개 명령이 7턴·3별 성공**하는 것을 재현했다. 이 일치가 원본의 모든 규칙을 입증하지는 않는다. `WinError 10054`의 발생 시점은 전달된 관찰이며 실기 재확인은 하지 않았다.

기존 사용자 봇 파일은 수정/복사 없이 별도 Python 프로세스로 실행했다. 공개 Stage 1에서 통신·12턴·3별 성공 및 소스 해시 불변을 확인했다. 세부 stdout과 결과는 비공개로 보관했다. 공개 범용 봇과 원본 참조 맵의 12회 검증은 별도 보고한다.
