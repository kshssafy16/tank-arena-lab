# Local TCP contract

주소 `127.0.0.1:8747` (변경 가능). UTF-8. 첫 요청은 `INIT nickname`, 최대 12글자 닉네임을 기록한다. 클라이언트는 **받은 상태 하나당 명령 하나**를 보내야 한다.

```
H W allies enemies codes
<공백으로 구분한 map, H행>
M hp direction normal mega
<나머지 allies행: symbol hp>
<enemies행: symbol hp>
<codes행>
```

서버는 마지막 행 뒤에도 줄바꿈을 보낸다. 암호 개수가 0이면 암호 행을 추가하지 않는다. `StateStream`은 수량만큼 완성된 행을 축적하며 여러 프레임이 한 recv에 와도 나머지를 보존한다. UTF-8 분할과 빈 암호 행을 보존한다. 원본 예제의 `recv(1024)` 한 번이 메시지 하나라는 가정은 TCP 보장이 아니다. 서버는 16×16 지도도 한 상태로 직렬화하지만 임의 OS/망에서 한 recv로 받는다는 보장은 하지 않는다.

명령: `A`, `F`, `F M`, `G PLAINTEXT`, `S`; 앞에 `U/D/L/R`을 붙여 회전할 수 있다. 문법 오류는 설정에 따라 턴 소모 또는 즉시 실패한다. 의도적인 pipelining은 지원하지 않는다. 한 읽기에서 여러 개의 줄 명령을 받으면 프로토콜 오류로 종료한다. 기존 프로토콜에는 turn ID가 없으므로 서로 다른 네트워크 시점에 도착한 낡은 명령을 항상 식별할 수는 없다.

## 두 가지 명령 구분 방식

**새 예제:** `INIT Bot\n`, `R A\n`, `R F M\n`. 줄바꿈은 패킷 경계와 무관한 명확한 구분자다. 이것은 로컬 서버의 명시적 확장이다. 이 예제의 newline 수신기는 최종 개행이 없는 원본 서버에서 바로 사용할 수 있다고 보장하지 않는다.

**기존 방식:** `INIT Bot `, `R A `, `R F M `. 수신 끝 공백 뒤 50ms 동안 추가 바이트가 없을 때 명령으로 확정한다. `F `가 완성된 일반 사격인지, 뒤늦게 `M `이 올 메가 사격인지 정보가 없으므로 공백만으로 모든 지연·분할 상황을 완벽히 구분할 수 없다. 이 제한을 숨기지 않으며 한 상태/한 명령과 localhost 사용을 전제로 한다. newline으로 보내면 이 모호성을 제거할 수 있다.

별점·Stage ID·턴 ID는 호환 상태 패킷에 추가하지 않는다. 헤더·지도·능력치만으로 봇이 다시 판단해야 한다. Stage 종료 직후에는 별도 종료 패킷 없이 다음 시도의 상태가 응답된다.

최종 종료 신호는 `0 0 0 0 0\n`이고 뒤이어 소켓이 닫힌다. 명령 수신 중 timeout/비정상 단절에서는 종료 신호 없이 EOF가 올 수 있다. 성공/실패 결과는 로컬 UI/JSON에서 확인해야 하며 **EOF 자체는 승리를 의미하지 않는다**. 연결 reset도 결과가 이미 확정된 뒤라면 성공을 실패로 덮어쓰지 않는다. 샘플 클라이언트는 zero header/정상 EOF를 종료로 처리한다. 독자 봇에서 예외 발생 시 traceback은 자신의 터미널에 남긴다.
