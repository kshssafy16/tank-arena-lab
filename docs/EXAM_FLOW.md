# Exam lifecycle

```
선택 → INIT 대기 → Stage 1/1차 → Stage 1/2차 → ... → Stage 6/2차 → 결과
                             어느 시도든 실패 → 즉시 결과
```

서버의 `Run` 하나가 전체 응시를 소유한다. 같은 클라이언트가 `INIT`을 한 번 보내고 각 상태에 명령 하나로 응답한다. 목표 파괴 명령을 처리한 뒤 같은 소켓의 다음 응답은 다음 시도의 초기 지도다. 이전 시도의 종료 지도를 먼저 보내지 않으므로 봇이 낡은 상태에 대해 명령을 생성하지 않는다. 중간 INIT/종료 패킷/재연결은 없다.

각 시도는 체력·방향·탄약·나무·지형 스크립트를 새로 만든다. 공개 시나리오는 재현 가능한 대칭 변형을 사용한다. 개인 지도는 반전하지 않으며 명시된 variants 중 직전 인덱스를 피한다. seed는 난수 재현 목적이고 공식 출제 규칙과 같은 난수열을 의미하지 않는다.

성공한 두 시도의 min을 단계 별점으로 확정한다. 첫 성공은 잠정값이며 합계에 확정 반영하지 않는다. 첫 시도 실패 또는 두 번째 시도 실패면 해당 단계는 0, 앞서 확정된 단계 점수는 보존한다. 전체 성공은 최대18별이다. 개별 연습에서는 한 시도 결과를 그대로 표시한다.

종료 이유는 `target_destroyed`, `turn_limit`, `player_destroyed`, `friendly_turret_destroyed`, `command_timeout`, `client_disconnected`, `protocol_error`, `invalid_command`(strict 설정), `user_reset`, `server_stopped`, `server_error`다. 빈 탄약은 기본 정책에서 감점/턴 낭비 이벤트이며 즉시 실패와 동일시하지 않는다. 성공은 규칙의 마지막 허용 턴에서도 가능하다. 개인 원본의 표시 카운터 보정과는 차이가 있을 수 있다.

시험에는 Pause/Step/Speed/수동 명령을 허용하지 않는다. Reset은 응시를 취소하고 현재 연결을 닫은 뒤 별개의 새 Run을 만든다. 각 연결에 generation을 붙여 이전 소켓의 예외가 새 Run을 실패로 바꾸지 못하게 한다. 동시에 접속한 두 번째 클라이언트는 거절한다.

결과/원문/명령/상태는 로컬에 저장된다. 시험 결과를 공식 시스템에 제출하는 기능은 없으며 서버에서 사용자의 봇을 자동 실행하지 않는다.
