## 일치하거나 근거가 확보된 동작

문서와 정적 메서드 분석을 통해 입력 헤더/기본 토큰/방향+행동/사거리3/피해30·70/독립 탄약/보급 인접/간격17/보급+1·상한10/60초/12회 동일 연결/최저 별점/중도 종료/zero header 종료를 확인했다. 자동 테스트는 **자체 구현의 일관성**을 검증하며 원본의 실기 관찰을 대체하지 않는다.

개인 프로필에는 정적 리소스에 있는 Stage별 지도 변형, 초기 능력치, 단계별 별점 경계를 저장했다. Stage6의 동적 지형 변경도 개인 설정에 포함했다. 근거를 public 규칙과 혼동하지 않는다.

## 명시적인 차이와 남은 불확실성

1. 공개 지도·점수표·보급 문구는 독립 제작이다. 원본 연습을 원하는 개발 PC 사용자는 `START_REFERENCE_WINDOWS.bat` 또는 `--profile private`로 실행한다. 공개 clone에는 개인 지도가 없다.
2. 매뉴얼의 모래 −10HP 서술과 달리, 설치본 정적 피해 함수는 팀전 모드에 조건부 적용된다. 공개게임은 모래 피해10, 개인 Stage 프로필은0으로 분리했다. 실기 비교는 필요하다.
3. Stage6 NPC 이동은 매 턴 지정 유닛의 방향을 선택하는 구조까지 확인했다. 원본 시간 기반 난수열을 복제하지 않았으며 로컬은 seed 기반이다. 지형 변경과 유닛이 겹치는 경우의 원본 표시/점유 세부도 실기 미검증이다.
4. 원본 턴 초과 시 표시 카운터 보정이 있다. 개인 프로필은 최대99행동과 확인한 별점 계산을 적용하며 초과 표시 숫자는 다를 수 있다.
5. 기존 끝 공백 명령은 50ms quiet window로 수용한다. 임의 지연에서 공백만으로 F/F M을 완전 구분하는 것은 불가능하다. 새 예제는 newline 로컬 확장을 사용한다. 원본 서버의 최종 개행·recv 경계에 그대로 쓸 수 있다고 보장하지 않는다.
6. 서버는 외부 봇을 직접 실행하지 않으므로 런타임 예외/수동 종료의 traceback을 소켓에서 읽을 수 없다. `client_disconnected`로 기록하고 봇 터미널을 확인한다.
7. 공식 서비스 인증, 실제 결과 제출, 팀전1v1/3v3, 지도 편집기, 원본 에셋 재배포는 없다.

## 이후 우선 검증

가장 필요한 추가 자료는 원본 로컬 연습에서 동일 명령으로 얻은 전후 상태 trace다. `tools/parity_check.py`로 개인 폴더 안에서 비교할 수 있다. 특히 Stage6 난수·변화 점유와 마지막 턴 표시, 메시지 개행·종료 reset 경계를 우선 확인한다. 공식 시스템에 접속하거나 평가를 자동 제출하지 않는다.
